# 书间 1.1：文风与创作技能

## 从哪里开始

打开一部作品，在写作台顶部点击“文风与技能”。这里保存的是这部作品的创作方法和表达档案，正文、正式事实和未来计划仍使用原有的编辑与确认流程。

一个常见用法是：先填写本书文风与人物声音，再在 AI 共创里选择本次需要的方法，预览材料后决定是否发起任务。也可以直接手写，或不选择额外方法。

## 六个内置方法

| 方法 | 适合解决的问题 |
| --- | --- |
| 场景目标与转折 | 场景缺少目标、阻力或结束时的变化 |
| 人物对白与潜台词 | 人物说话同声、解释过多、潜台词不足 |
| 慢热关系推进 | 关系变化缺少行动积累，或重复依赖某种套路 |
| 视角与连续性核对 | 知情、时间、物品状态和事实依据需要回查 |
| 文风保护与分层修订 | 改稿时保留细节、人物口气和有意留白 |
| 稿件清洁检查 | 提示残留、占位内容和明显相邻重复 |

不同方法支持的任务不同，AI 面板只显示适合当前任务且已启用的方法。每次最多选择三个，可为本次补充要求。

这些方法仍服从当前任务的操作范围、输出格式、预算、版本检查和作者采纳。选择某个方法不会自动定稿，也不会把模型建议确认为事实。

## 编辑自己的方法

内置方法保留原版。在技能页修改标题、说明或方法正文后，点击“保存为我的技能”，会建立当前作品的独立副本。自定义技能使用“保存新版本”，旧版本及历史任务保留。

“查看技能历史”可以查看旧内容；把旧内容载入为编辑稿后，仍需明确保存，形成新版本。也可以另存副本。

每类任务可设置最多三个常用方法，保存“创作档案”后生效。发起任务时仍可调整。停用内置方法需要保存档案；自定义方法的启停随技能版本保存。若自定义方法正在某类任务的常用列表里，先移除并保存档案，再停用或改变适用任务。

档案和技能都有版本检查。其他页面已更新时，保存会提示冲突并保留本页填写内容。可先用“导出填写内容”保留本机稿，再决定如何合并。

## 导入、导出与参考资料

“导出技能”生成书间技能 JSON 包，包含声明式方法、适用任务、来源、许可和文本资源。导入会创建独立副本，不覆盖现有技能。

也可导入带名称和描述的 `SKILL.md`，例如：

```markdown
---
name: dialogue-with-intent
description: 用于讨论、起草或改稿时检查人物各自的意图。
license: MIT
---
区分说话者想得到什么、愿意说什么和暂时不愿说什么。
保留作者要求和选区之外的内容，输出格式仍由当前任务决定。
```

这是受限的文本导入，并非完整的外部 Agent 插件安装。工具声明、脚本和包外文件不会执行或读取；不支持的元数据会提示处理。外部链接不会自动联网获取。

引用本包参考文件时，应把资料正文一同放在技能包内。编辑器可以添加 `.md` 或 `.txt` 文本参考，使用 `references/example.md` 这样的包内相对路径。缺失引用和越界路径会被拒绝。发起任务时，只有明确选中的参考资料进入实际提示；保留在技能定义中的其他参考仍可用于以后选择。

导入他人方法时保留其来源与许可说明。不要把需要任意工具、文件读写或网络执行的技能当作本版已支持的能力。

## 本书文风与人物声音

“本书文风”可填写叙述方式、语气与幽默、句式与节奏、希望避免的表达，以及有权使用的短范例。保存后参与新任务，既有任务保留当时的档案依据。范例只作表达参考，不自动变成剧情事实。

“人物声音”保存人物名称、别名、声音特点和对白示例。每次任务明确选择最多八个人物声音，未选中的卡片不送入模型。声音卡不能扩大角色知情范围；人物真正知道什么仍以故事资料和正文证据为准。

文风没有统一的“好文笔”分数。当前任务要求可以针对表达方式作具体调整，但不会绕过正式事实的确认过程。

## 偏好案例：先保留依据，再确认

可以手动添加案例，也可以在已有起草/改稿记录中点击“记录作者改稿偏好”。后者把原始模型输出和当前保存稿各取最多 6000 字符作为填写起点，保留来源任务与章节。请选取真正相关的原句和改稿，并补充理由、适用条件及例外。

- **待确认**：保存案例，暂不参与新任务。
- **已确认**：作为表达偏好供新任务参考，需要写明理由。
- **已撤回**：继续保留记录，不再参与新任务。

一次删除不自动成为永久禁令；未修改的文字也不等于默认认可。案例不能替代正式事实。需要回看旧档案时，可用“档案历史”，载入后保存为新的档案版本。

## 预览材料与费用

在 AI 共创选择任务、方法、人物声音与本次资料，然后点击“预览本次材料与费用”。界面会先保存当前编辑，再计算本次材料；预览操作本身不创建任务、不新增正文留稿，也不调用模型。

预览展示模型、预计输入和预留输出、按已配置单价估算的调用费用、将发送的材料，以及因输入预算不足未装入的条目。未知价格保持未知；配置费用上限但缺少价格时会说明不能可靠限制费用。

“按此材料开始任务”会重新核对正文、档案、技能、材料和模型设置。已经变化时，需要返回重新预览；不会沿用已过期预览直接计费。也可以返回调整后按普通“开始”按钮创建一个基于当前材料的新任务。

Token 是保守估算，服务商用量和账单为准。显示的预留费用针对本次调用，后续修正或重试仍可能产生费用，并继续受现有任务/日预算控制。

## 查看历史提示与基础清洁检查

创作记录中的“创作方法与实际提示快照”保存初次请求的任务规则、材料、技能版本与哈希。技能或档案更新不会改写旧任务的快照。若发生格式修正或重试，可在调用记录中查看各次请求的实际提示；旧任务缺少完整快照时会如实说明。

“重新尝试”创建独立任务：保留原方法的版本、补充要求和已选参考，使用当前保存的章节、创作档案与模型设置。停用的方法仍会阻止重试；如果希望使用更新后的方法，重新选择并发起新任务。重试不会覆盖旧结果。

“基础稿件检查 · 不调用模型”检查已保存稿中的几类明确残留，并给出原句。它不自动改稿、不决定文学质量，也不阻止作者定稿；正文变更后应重新检查。

## 离线评测与备份

创作记录可导出“冻结评测样本”。源码环境运行 `pnpm eval:creative` 可验证确定性案例；`pnpm compare:creative` 可离线整理一份样本，或检查两份已完成样本是否满足严格的 Skill 比较条件。完整步骤见 `docs/QUALITY_COMPARISON.md`。工具不会自动生成第二份模型输出，也不会用模型自评决定是否采纳正文。

完整作品备份包含自定义技能、资源、技能历史、文风、声音、偏好案例、档案历史与任务提示/调用快照；恢复仍作为独立作品加入。1.0 的旧备份可恢复，未有创作档案的作品从空白档案开始。历史快照保留原始执行内容，恢复后的引用与新任务使用恢复作品自己的记录。

本版仍沿用 PostgreSQL 和 SQLite 两种实际后端，API 密钥和数据库密码继续放在作品数据之外。导出的作品、技能和评测样本均不携带连接密钥。
