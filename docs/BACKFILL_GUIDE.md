# 从正文回填知识与图谱

打开作品，在编辑器工具栏选择 **正文回填**；移动端从“工具”打开。

1. 先为要分析的章节定稿。面板默认选择尚未回填或定稿已经更新的章节，也可自行选择。
2. 点击“预览分析材料与费用”，核对章节、输入材料、Token 与费用；再确认调用模型。
3. 多章按顺序分析。可以停止队列；已生成的任务保留，刷新后可再次打开。失败任务可选择章节后重新分析。
4. 在任务中打开“查看回填差异”，检查实体、关系、状态及每条原文证据。匹配已有实体，遇到同名人物时明确选择，也可以新增独立实体。
5. 确认后一次性写入知识卡、图谱关系及章节状态；分析本身不修改正式资料，回填不修改正文，也不再次调用模型。

## 更新与保护

- 新增实体使用本章事实和证据。匹配已有实体时保留原档案，新事实作为本章状态保存，避免后文信息提前进入旧章。
- 新增资料、关系和状态默认仅作者可见，不自动推断人物知情范围。可在资料与图谱中进一步编辑。
- 定稿改变后，该章重新显示为待分析，旧分析不能用于新定稿；旧证据和历史继续保留，需要复核的档案会提示。
- 模型引文必须能在指定定稿段落中找到；伪造或缺少证据的候选会使任务失败，不写入知识和图谱。
- 确认时重新检查正文和图谱指纹；其他页面修改后需重新预览。回填在事务中完成，重复确认同一任务不会重复插入。
- 旧关系和旧状态不会因新结果未提及而自动撤回。可查看已有图谱对照，再在图谱中处理不再适用的记录。
- 来自未定稿草稿的普通“整理资料”功能仍保留；本流程只处理正式定稿。草稿有修改时明确使用上次定稿，需重新定稿后才分析新内容。

回填记录随完整备份导出、恢复和数据库迁移，删除作品时一起清理。批量队列在面板打开期间顺序执行；关闭服务会中断当前任务，未开始的章节需重新选择分析。不会后台自动调用个人模型。

验证：固定本地模型样本覆盖实体匹配、原文证据、关系/状态、重复确认、来源变化、并发预览、备份恢复及删除；SQLite 与真实 PostgreSQL 均验证。浏览器验收覆盖两章顺序分析、明确确认、实体去重和移动端。
