# 项目优化检查（2026-11-10）

> 六项目标已于 2026-11-11 完成，具体实现与验收见 [优化完成记录](OPTIMIZATION_RESULT-2026-11-11.md)。以下保留当时的检查依据。

## 本次完成

- 旧库小说导入工具：只读一致性快照、导入前备份、整体事务和重复导入检查；保留最新草稿、原正文与历史版本、人物地点等设定及伏笔。旧审阅、生成会话、事件和日志保留在私人源快照中，不直接转换为新系统任务。
- 小说和章节删除：确认提示、自动备份、草稿版本校验、运行中任务保护；删除整部小说时清理关联资料，保留不含提示词与正文的计费记录，避免清空当日预算。
- 空作品可重新新增章节；删除章节保留序号，避免改变设定的生效时间线。
- 删除备份只读取目标小说，避免遍历整个作品库。

## 建议顺序

| 优先级 | 发现与依据 | 建议 | 收益与验收方式 |
| --- | --- | --- | --- |
| 高 | 生产构建主 JS 约 830 KB，gzip 约 256 KB，构建器提示超过 500 KB；App 同步导入书架与编辑器，编辑器同步导入多个工具面板 | 用动态导入按编辑器、模型设置、图谱、策划和创作工具拆分加载 | 记录书架首屏 JS 与打开编辑器耗时，确认懒加载失败可重试 |
| 高 | 正文证据、规划和 AI 快照形成历史引用，删除源章节会破坏出处和恢复校验，因此本次使用拒绝删除保护 | 增加引用明细面板和“归档章节”，明确显示依赖来源，再设计带影响预览的解除关联流程 | 能快速知道为什么不能删除，历史快照仍能回查、备份仍能恢复 |
| 中 | 每次删除都会保留 JSON 安全副本，目前没有备份管理界面 | 增加备份列表、恢复预览、容量统计和用户可配置的保留周期 | 无需寻找文件；清理前显示数量和空间，避免自动删掉唯一副本 |
| 中 | 大量模块通过 payload JSON 保存关联；删除时需要集中检查多个模块 | 建立统一的引用查询和删除生命周期接口，并给常用引用建立结构化索引 | 新增模块不漏清理；用整部删除与备份往返测试验证完整性 |
| 中 | AI 服务约 56 KB、AI 面板约 31 KB、图谱面板约 32 KB，生成执行、费用和交互职责集中 | 按任务执行、上下文、备份与预算拆分服务；按编辑与浏览拆分面板 | 保持现有接口与测试，降低修改一项功能时的关联风险 |
| 中 | 移动编辑器工具栏入口密集，390 像素宽度下文字较小 | 把次要功能集中到工具菜单，保留正文、保存和章节切换入口 | 在 390/720/1440 像素验收，无横向溢出且操作目标易点按 |

优先完成拆分加载和引用明细。其余可结合实际作品规模安排，暂不重写存储层。
